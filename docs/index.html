⚡ B — Workflow App (fixed, predictable steps)

A workflow uses a predefined code path. Here's a prompt-chaining script: extract → validate → format. Each step is deterministic.

pythonimport anthropic, json
client = anthropic.Anthropic()

def step(system, user):
    r = client.messages.create(model="claude-opus-4-20250514",
        max_tokens=1024, system=system,
        messages=[{"role":"user","content":user}])
    return r.content[0].text

raw = "Invoice 4471, ACME Corp, $1,240.00, due 2026-06-15"

# Step 1: extract  ->  Step 2: validate  ->  Step 3: format
extracted = step("Extract invoice fields as JSON.", raw)
validated = step("Check JSON for missing/invalid fields. Return JSON + 'valid' bool.", extracted)
report    = step("Turn this validated JSON into a one-line summary.", validated)
print(report)
Goal: learn workflows — predictable, cheap, testable. Use when the steps are known in advance.

🤖 C — Agent Prompt (autonomous, tool-driven)

An agent directs its own steps using tools in a loop. Use this as the system prompt for an agent that has search + file tools.

promptYou are an autonomous research agent.

Goal: answer the user's question with a sourced, accurate summary.

Loop until done:
1. THINK: decide the single next action that makes most progress.
2. ACT: call exactly one tool (web_search, fetch_page, save_note).
3. OBSERVE: read the result; note what you learned.
4. Repeat. Stop when you can fully answer with cited sources.

Rules:
- Prefer primary sources. If two sources conflict, say so.
- Keep tool inputs minimal and outputs concise to save context.
- If a tool errors, adapt — do not retry the same call blindly.
- End with: a 3-bullet answer + a Sources list.
Goal: learn agents — the model plans and chooses actions itself. Use for open-ended tasks where steps can't be scripted.

Agentic Architecture & Orchestration

27% ▼

Single-Agent Loops (ReAct / Tool Loop)

The fundamental agent pattern: model reasons, calls a tool, observes the result, then loops until the task is done.

Use case: A research assistant that searches the web, reads pages, and synthesizes an answer across multiple turns.
pythonimport anthropic
client = anthropic.Anthropic()

messages = [{"role": "user", "content": "Find today's top AI news"}]

while True:
    resp = client.messages.create(
        model="claude-opus-4-20250514",
        max_tokens=2048,
        tools=tools,
        messages=messages,
    )
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":
        break                          # task complete
    tool_results = run_tools(resp.content)
    messages.append({"role": "user", "content": tool_results})

Multi-Agent / Orchestrator–Worker

A lead "orchestrator" agent decomposes a task and delegates subtasks to specialized "worker" subagents running in parallel.

Use case: A coding agent spawns separate workers for frontend, backend, and tests, then merges their outputs.
pythondef orchestrate(goal):
    plan = ask_lead(f"Break this into subtasks: {goal}")
    results = []
    with ThreadPoolExecutor() as ex:        # run workers in parallel
        futures = [ex.submit(worker_agent, t) for t in plan.subtasks]
        results = [f.result() for f in futures]
    return synthesize(goal, results)

Workflows vs. Agents

Workflows = predefined code paths (predictable, cheaper). Agents = the model dynamically directs its own steps (flexible, for open-ended tasks). Choose the simplest that works.

Use case: Use a fixed prompt-chaining workflow for invoice extraction; use a full agent for "debug this unknown failure."

Routing & Evaluator-Optimizer Loops

A router classifies input and sends it to the right handler. An evaluator-optimizer loop generates a response, critiques it, and refines until quality criteria are met.

Use case: Support triage routes billing vs. technical tickets; a writing agent self-reviews drafts before returning them.

State, Memory & Handoffs

Persisting conversation state, passing context between agents, and resuming long-running tasks. Keep a durable log so an agent can recover after interruption.

Use case: A multi-day project agent stores progress in a database and resumes exactly where it left off.

Tool Design & MCP Integration

18% ▼

Tool Definition & JSON Schema

Tools are described to Claude with a name, a clear description, and an input_schema (JSON Schema). Good descriptions matter more than the code itself — they drive correct tool selection.

Use case: Give Claude a get_weather tool so it stops guessing and fetches live data.
json{
  "name": "get_weather",
  "description": "Get current weather for a city. Use when the user asks about temperature or conditions.",
  "input_schema": {
    "type": "object",
    "properties": {
      "city": { "type": "string", "description": "City name, e.g. 'Austin, TX'" },
      "unit": { "type": "string", "enum": ["celsius", "fahrenheit"] }
    },
    "required": ["city"]
  }
}

The Model Context Protocol (MCP)

MCP is an open standard ("USB-C for AI") that connects Claude to external tools, data, and prompts through a uniform interface. Servers expose tools, resources, and prompts; clients (like Claude) consume them.

Use case: Connect Claude to GitHub, a database, and Slack through three MCP servers without writing custom glue for each.

Building an MCP Server

Define tools with a small SDK; the framework handles the protocol handshake, schema exposure, and transport (stdio or HTTP/SSE).

pythonfrom mcp.server.fastmcp import FastMCP
mcp = FastMCP("my-tools")

@mcp.tool()
def lookup_order(order_id: str) -> dict:
    """Fetch an order's status and items by ID."""
    return db.get(order_id)

if __name__ == "__main__":
    mcp.run(transport="stdio")

Connecting MCP in Claude (config)

Register servers in the client config; Claude auto-discovers their tools at startup.

json{
  "mcpServers": {
    "my-tools": {
      "command": "python",
      "args": ["server.py"],
      "env": { "DB_URL": "postgres://localhost/app" }
    }
  }
}

Tool Reliability & Error Handling

Return structured errors so Claude can recover, validate inputs server-side, set timeouts, and keep tool outputs concise to save context. Mark tools read-only vs. write for safety.

Use case: A payment tool returns {"error": "card_declined", "retryable": false} so the agent stops retrying.

Prompt Engineering & Structured Output

20% ▼

Clarity, Roles & System Prompts

Be explicit and specific. Use the system parameter to set role, tone, and constraints — it carries more weight than inline instructions.

pythonclient.messages.create(
    model="claude-opus-4-20250514",
    system="You are a senior SQL reviewer. Be terse. Flag only real bugs.",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Review: SELECT * FROM users"}],
)

XML Tags for Structure

Claude is specifically tuned to respect XML tags. Use them to separate instructions, context, examples, and data — and to request a structured response shape.

text<instructions>Summarize the document in 3 bullets.</instructions>
<document>
{{LONG_TEXT}}
</document>
Put your answer inside <summary> tags.

Few-Shot Examples & Chain-of-Thought

Show 2–5 examples of the input/output pattern you want. For hard reasoning, ask the model to think step-by-step inside a <thinking> block before answering.

Use case: Classification accuracy jumps when you provide labeled examples plus a reasoning scratchpad.

Guaranteed JSON / Structured Output

Force valid JSON by defining a tool whose schema is your output format, then read the tool input. This is far more reliable than asking for "JSON only."

pythontools = [{
  "name": "record_sentiment",
  "description": "Record extracted sentiment",
  "input_schema": {
    "type": "object",
    "properties": {
      "sentiment": {"type": "string", "enum": ["pos","neg","neutral"]},
      "score": {"type": "number"}
    }, "required": ["sentiment","score"]
  }
}]
resp = client.messages.create(
    model="claude-opus-4-20250514", max_tokens=512,
    tools=tools,
    tool_choice={"type": "tool", "name": "record_sentiment"},  # force it
    messages=[{"role":"user","content":"I love this!"}],
)
data = resp.content[0].input   # -> {"sentiment":"pos","score":0.95}

Prefilling & Output Control

Prefill the assistant's turn (e.g., start with {) to skip preambles and lock the format. Combine with stop_sequences for tight control.

pythonmessages=[
  {"role": "user", "content": "List 3 fruits as JSON"},
  {"role": "assistant", "content": "["}   # prefill forces array start

Context Management & Reliability

15% ▼

The Context Window Budget

Every token (system prompt, history, tool results, docs) competes for a finite window. Treat context as a scarce resource: include only what's relevant, drop the rest.

Use case: Trimming verbose tool outputs to summaries lets a long agent run continue without truncation.

Prompt Caching

Mark large, stable prefixes (system prompt, docs, tool defs) as cacheable to cut latency and cost dramatically on repeated calls.

pythonsystem=[{
  "type": "text",
  "text": large_knowledge_base,
  "cache_control": {"type": "ephemeral"}   # cache this block
}]

RAG & Retrieval

Instead of stuffing everything in context, retrieve only the most relevant chunks at query time via embeddings + vector search. Keeps context lean and answers grounded.

Use case: A docs chatbot retrieves the top-5 relevant sections rather than the entire 500-page manual.

Compaction & Summarization

For long sessions, periodically summarize older turns into a compact memory and discard raw history — preventing window overflow while preserving key decisions.

pythonif token_count(history) > THRESHOLD:
    summary = summarize(history[:-6])     # keep last 6 turns verbatim
    history = [{"role":"user","content":f"Summary: {summary}"}] + history[-6:]

Reliability: Retries, Idempotency & Guardrails

Wrap calls with exponential backoff, validate every output against a schema, add guardrails for unsafe actions, and make write-tools idempotent so retries don't double-execute.

pythonfor attempt in range(3):
    try:
        out = call_claude(msg)
        validate_schema(out)          # reject bad output
        break
    except (RateLimitError, SchemaError):
        time.sleep(2 ** attempt)        # exponential backoff

Evaluation & Observability

Build eval sets, log every prompt/response/tool call, and track quality metrics over time. You can't improve reliability you can't measure.

Use case: A regression suite of 50 graded prompts runs in CI before any prompt change ships.

Hooks — react to events

sample ▼

Lifecycle event scripts

Hooks run at events like PreToolUse (before a tool runs — can approve/deny), PostToolUse (after — e.g. auto-format), Stop, and SessionStart. Two flavors: a shell command or a prompt hook that asks the model to judge.

bash# file: .claude/hooks/block-secrets.sh — a PreToolUse guard
#!/usr/bin/env bash
# Claude passes the tool input as JSON on stdin
input=$(cat)
if echo "$input" | grep -Eq '(API_KEY|SECRET|PASSWORD)\s*='; then
  echo '{"decision":"deny","reason":"Possible secret in write."}'
  exit 0
fi
echo '{"decision":"approve"}'

A prompt hook instead lets the model decide — handy when rules are fuzzy:

json{
  "PreToolUse": [{
    "matcher": "Write|Edit",
    "hooks": [{
      "type": "prompt",
      "prompt": "Check this write for secrets, system paths, or path traversal. Return 'approve' or 'deny'."
    }]
  }]
}
